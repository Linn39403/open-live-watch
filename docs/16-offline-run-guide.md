# Offline milestone run guide

## Offline demo

1. Run `npm ci`, then `npm run desktop` (or browser-only `npm run dev`). A blank instrument project opens. Choose File → New project, enter a name and press Create project to start your own screen. Blank projects have no implicit motor source or bindings. File → Open motor demo explicitly opens the optional Motor lab sample.
2. Click a toolbox instrument to add it. Click an instrument to select; Shift-click for multiple selection. Drag freely, resize from eight handles, or drag the circle above it to rotate. Zoom supports 50%, 100%, 150%, 200%. Snap grid can be disabled; Alt temporarily bypasses snap. Arrow keys nudge; Shift-arrow moves ten units. Escape cancels a gesture; Ctrl/Command-Z undoes and Ctrl/Command-Shift-Z redoes.
3. Every added instrument starts unbound. While designing, unbound instruments display their original face with clearly labeled sample previews; these are layout aids, not live readings. In the explicit motor demo, bind compatible numeric/bool symbols in Properties, or drag a Symbol Browser row onto an instrument. Unsupported source providers and unresolved symbol names show a labeled unresolved Design preview while stopped and no fabricated reading during Run. Properties geometry lock is session-local.
   In Properties → Appearance, choose Green, Blue, Orange, Red, Purple, Teal or Slate blue, or open the Accent picker for a custom color. Enter an exact `#RRGGBB` value in the editable hex field beside either picker for precise colors. Radial gauges also have a separate Needle picker. Colors update the selected instrument immediately and support Undo/Redo, duplication, shared floating Properties, and save/reopen. Incomplete/invalid hex drafts are not applied; leaving an invalid field restores the current color with visible feedback. Stop Run mode before editing appearance. Restore default colors clears overrides and restores the instrument's default accent plus red gauge needle.
4. In the motor demo, click Run. Readings now come from a 20 Hz worker-based simulated motor. Blank projects can Run after configuring a supported offline source; the motor demo is optional. Slider and switch inputs write only writable simulated symbols with a current session epoch; Stop rejects writes and restores editing. Slider commits on pointer release or keyboard navigation release. The button is explicitly a toggle control, not a momentary target write.
5. Stop; File → Save project saves an existing file, or asks for a destination for a new project. Save as always chooses another destination. Open project reopens saved JSON. New project, Open project and Open motor demo offer Save changes, Discard changes or Cancel before replacing a changed project; canceling/failed native saves keeps the current project. Replacements clear selection/history/file association as appropriate, stop simulation and advance the session epoch. Desktop uses native dialogs and Rust JSON-schema/semantic validation; browser uses download/upload. Native saves write/sync a temporary sibling and atomically replace the destination, preserving the previous file if validation or write fails. Workspaces larger than 10 MB are rejected natively.
6. Drag panel headers onto left/right/bottom panel areas, or use the dock-position selector. Press ↗ for a native floating window in the desktop build. A floating Properties view can edit the selected widget; Symbol Browser follows the same simulated values. Dock returns the panel to the chosen edge. Closing a floating panel returns it to its default dock; closing the main window exits all windows. Floating Explorer and Toolbox are currently views; toolbox addition stays in the main window.
7. View → Restore default layout restores panels without changing widgets. File → Export recent CSV downloads the bounded recent speed history (120 samples).

## Configure your own project and graph

1. Create a blank project and choose Design → Configure data sources (also available in Explorer). Add an offline source such as `lab`. Add a numeric `temperature` variable with units `°C`, initial 25, min 0, max 100, Sine waveform and 2,000 ms cycle. Add a numeric `setpoint` with Constant / manual, initial 25, min 0, max 100, and Allow manual writes. Apply sources. For boolean indicators/controls choose Boolean with Constant / manual or read-only Toggle waveform.
2. Add a gauge and choose Properties → Binding → Source / variable = `lab / temperature`. Set display min/max/precision separately from provider limits. Gain and offset convert raw values to engineering units; controls invert this conversion on writes. Boolean bindings use identity mapping. Refresh interval is rounded up to 50 ms ticks (60 ms becomes 100 ms); faster requests clamp to 50 ms. The waveform cycle controls generated signal repetition, not display refresh.
3. Add a slider, bind `lab / setpoint`, allow control writes, and set its display range to the source's range after applying gain/offset. Add a graph and bind its ordinary Binding to `lab / temperature` (Y). Time-series mode uses elapsed simulation seconds on X. For XY choose the mode and select `lab / setpoint` in Graph X; X has its own gain/offset/units/refresh. Pairing uses the same acquired frame, never unrelated latest values.
4. Press Run. Source variables generate values in the single worker; controls write only catalog-authorized constant/manual variables. Generated sine/ramp/toggle signals are read-only. Acknowledged writes update runtime values; saved initial values remain unchanged. Stop retains the acquired graph; starting Run, replacing a project or changing/undoing source configuration begins a fresh session and clears graph history.
5. Save project and reopen it. Sources, variable types/access/waveforms/cycles, instrument bindings/mapping/display scale, graph modes/X/Y/history settings and colors all persist. Reopening restores configured initial values in stopped mode, even when the catalog is identical to the prior project. Source edits validate existing bindings; unbind instruments before removing referenced variables.

Limits: eight sources and 128 catalog variables total, including the four legacy motor signals. Offline numeric configuration is bounded to ±10¹² and waveform periods to 100–3,600,000 ms. Acquisition retains 600 coherent frames (30 seconds at 20 Hz); graph maximum points is 10–600 and is further limited by retained frames, visible window and effective refresh. Each graph has one Y series and optional numeric X; X axes auto-scale, Y can auto-scale or use Display scale limits. Bad-quality/missing samples break line segments, including faults inside refresh decimation intervals. Layout previews never enter graph history.

One control write may await a result at a time. The worker remembers at most 128 processed operation IDs per Run and rejects further writes until Run is restarted, preventing replay with bounded memory. A missing result after two seconds is shown as unknown, without retry. Provider protocol structure, epoch/catalog/command revisions, sequences, types and ranges are validated at receiving boundaries. Only offline and legacy motor providers run; no external device/network transport exists. CSV remains the legacy recent motor-speed snapshot, not a generic source/graph log.

## Implementation mapping

`src/model.ts` contains workspace validation, bounded undo/history, project reset and legacy motor stepping. `src/provider.ts` defines source-qualified catalogs, validated protocol envelopes, binding reads/writes and coherent batch application. `src/engine.ts` is the pure offline worker engine; `src/simulator.worker.ts` runs it at 20 Hz. `src/SourceEditor.tsx` and `src/BindingEditor.tsx` configure sources and typed bindings; `src/Graph.tsx` maps coherent samples and renders bounded plots. Only the main window starts a worker. Main-window document state is authoritative. Floating views send commands through Tauri application events and receive validated shared snapshots; they do not create acquisition workers. Epoch/catalog/command revisions reject delayed frames and writes, and sequence/timing cannot rewind. Received samples are never echoed back as worker configuration. Desktop loads/saves use `src-tauri/src/main.rs`; both Rust and the frontend validate the same version-1 JSON schema plus ID/source/variable/type/access/range semantics. Frontend schema validation is generated statically from the shared schema before dev/test/build; runtime never compiles validation code, keeping the native CSP free of unsafe-eval. Local panel placement persists separately from portable workspace geometry. On relaunch, previously floating entries return to default docks.

Appearance persists in optional `settings.color` and `settings.needleColor` fields, each strictly `#RRGGBB`. Neutral silver/ivory physical faces use restrained defaults: blue radial/linear/slider, teal numeric readout/trim, amber LED/button, slate blue switch and red thermometer; gauge needles remain red. This intentionally replaces the earlier universal green default for workspaces without explicit color fields. No schema migration is needed, and every saved custom accent/needle override is preserved exactly. Green remains available as a preset. The accent affects radial range/readout, linear/thermometer fill, LED ON/glow, switch ON, button face, numeric readout/trim and slider track/thumb where the host supports accent colors. Value text is automatically darkened; button/switch text uses black or white based on the accent's luminance. OFF states remain neutral and visibly separate from colored ON states. This is per-instrument appearance; configurable graph series also use their saved accent color. The operating system's window accent is unchanged.

## Explicit remaining limits

- Full AC14/AC15 acceptance remains open: no macOS/Linux runtime testing, second-monitor/DPI/monitor-removal evidence, split-tree docking, tab stacks, tab reordering, auto-hide, dock previews, or persisted native window bounds.
- This prototype edits only the first screen. Additional screens survive save/load but have no UI navigator. Geometry lock is session-local and not serialized/shared to floating inspectors.
- Panel edge arrangement is a simple persisted mapping, not the planned versioned layout tree. Empty docking regions remain available. Dock drags have no custom preview or Esc cancellation.
- Widget grouping, marquee selection, copy/paste, smart guides, distribute, z-order commands and screen floating are deferred. Multi-selection move, duplicate and align-left are present. Rotation handle uses horizontal drag delta in degrees, not an angular pointer gesture.
- The legacy demo chart/CSV shows recent motor speed. Configurable graph elements now plot source-bound time/XY data. CSV remains a legacy bounded snapshot with sample-relative time, rather than generic continuous logging with wall-clock timestamps, quality/catalog epochs or recovery.
- Native saves are atomic replacements, not autosave/recovery sessions. Unsaved-change prompts protect New/Open/demo replacement; closing the main application window still exits without an unsaved-change prompt. Browser save marks the current document saved after initiating its download; the app cannot confirm that the browser finished writing it. Runtime state is hosted by the main frontend; durable Rust session ownership is a later milestone.
- New projects start source-free, then may configure offline numeric/boolean sources in the UI. Legacy `mock-motor` remains available as an example. External providers, embedded connections, discovery, ELF/DWARF, firmware, hardware writes and device transports are deferred.
- The current replay cache limits control writes to 128 processed operations per Run; a later monotonic operation-counter contract should remove that practical interaction limit while preserving bounded replay protection. Graphs have one series, X auto-scaling and bounded in-memory simulated acquisition; no triggered target scope or generic continuous logging exists.
- The generated Windows executable is unsigned. Signing, notarization, release installers and production distribution validation remain open.

Architect Windows GUI verification for the source/graph update passed: native open, new gauge binding and free movement, time/XY acquisition, manual slider writes, Stop capture retention, native Save As and reopening the same-source document with initial values restored.
