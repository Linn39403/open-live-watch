# Offline designer run guide

## Start and configure

Run `npm ci`, then `npm run desktop`; browser preview is `npm run dev` at port1420. Build native with `npm run desktop:build -- --no-bundle`. Check with `npm test` and `cargo test --manifest-path src-tauri/Cargo.toml`. All validation generation runs before dev/test/build.

The app starts blank. File → New project names your project; File → Open motor demo explicitly opens the optional simulator. Click a toolbox instrument to add it at a bounded vacant position. Unbound Design previews are labeled layout samples, never acquired data. Appearance offers restrained per-kind colors, presets and exact custom hex entry; explicit saved overrides remain unchanged.

Design → Configure data sources adds up to eight offline sources and 128 total typed variables. Create a numeric Sine/Ramp variable for acquisition, or Constant/manual numeric or boolean variable for permitted controls. Generated waveforms are read-only. Limits are ±10¹²; waveform cycles are100–3,600,000ms. Bind selected instruments through Properties → Binding. Gain/offset map raw to engineering values; writes invert this conversion. Boolean mapping must be identity. Refresh requests round up to50ms worker ticks (60ms becomes100ms).

Add a graph: ordinary Binding is primary Y. Choose Time series or XY, with an independent numeric Graph X for XY. Graph series adds up to seven additional named numeric Y bindings, each with color and visibility; the primary plus extras totals eight. X is shared for coherent XY pairing. Stable automatic Y bounds union transformed catalog ranges; manual Display limits take priority. Mixed units are explicitly labeled. Line and Points modes persist; absent XY trace mode intentionally defaults to scatter. The latest displayed values and effective refresh are labeled. Min/max reduction preserves coherent X and Y extrema in XY, vertical extrema in time plots, and quality gaps; isolated/current points remain visible. Acquisition retains600 global frames/30 seconds; each graph has10–600 plotted-point capacity. Rendering never feeds decimation back into acquisition or logging.

Run acquires all configured sources through one worker. Stop freezes capture and enables editing. Slider commits on release; switch writes booleans. Button Properties selects Toggle, Momentary hold or Repeat, with200–5,000ms repeat interval. New buttons default Momentary; legacy unspecified buttons retain Toggle. Catalog permissions are authoritative. One result may be pending; `epoch:counter` IDs provide bounded monotonic replay protection without a128-operation session cap. Unknown outcomes stop/invalidate the session and never retry automatically.

## Screens and freeform editing

The screen tab bar adds, renames, switches and deletes screens; the last screen cannot be deleted. Views share source/session state. Shift-click or marquee selects multiple widgets. Move, eight resize handles, angular rotation, numeric Properties, keyboard nudge, zoom and optional snap are supported. Alt bypasses snap; Escape restores the pre-gesture geometry/selection. Ctrl/Command-Z and Shift-Z undo/redo.

Group/Ungroup preserves child offsets; group resize is uniform. Numeric size changes reject any group member below64 pixels. Locks persist, and a locked group member protects collective geometry. Copy/Paste regenerates IDs and preserves relative geometry and validated bindings; align/distribute/z-order operate group bounding units. Intentional overlap remains legal; selected overlap is indicated. Screen/document undo preserves portable geometry, bindings and colors.

## Docking and native views

Drag a dock tab or panel header to the preview's Top/Left/Right/Bottom region or Tab target. Tabs can reorder; split separators support pointer and arrow-key resizing, with Escape/pointer-cancel restoring the drag start. Auto-hide supports all four edges; click an edge tab to open its drawer. View can save/load/delete up to eight named local layouts or restore defaults.

The layout is a validated version2 tree, separate from workspace files: maximum32 nodes, depth8,16 floating views, unique panel identity and one main canvas. Native floating panels share authoritative document/session state. Float screen view creates an independent native canvas retaining its own screen identity; writes and geometry commands target that screen, rather than whichever screen is active in the main view. Removed-screen views close without deleting other document content. Native view close returns fixed panels to their default dock and hides screen views; main close offers document protection then exits the app.

Floating restore stores logical client size and monitor work-area-relative offsets with a monitor hint. Restoration uses explicit physical desktop position and logical size, clamps within the available work area and accounts for decorations. Disconnected monitor hints fall back to an available display. Mixed-DPI coordinate and decoration roundtrips have automated coverage; actual second-monitor/DPI runtime remains unverified. Previously saved bounds without a monitor hint are conservatively clamped on an available display.

## Recovery, controls and recording

The editor now supports multiple screens, marquee selection, saved groups/locks, relative copy/paste, z-order, group-aware alignment/distribution and collective group transforms. Group resize preserves aspect ratio; numeric size edits reject changes that would make another group member smaller than 64 pixels. New instruments search a bounded set of vacant positions; intentional overlaps remain allowed and are indicated for the selection.

Close and project replacement offer Save/Discard/Cancel. A validated recovery snapshot is written after a 500ms debounce; startup offers Restore or Discard, and corrupt snapshots are reported and preserved until explicit discard. This is a recovery snapshot, not a background save of the project file. Recovery is limited to a 10MiB workspace plus 1KiB metadata.

Momentary and repeat buttons distinguish physical hold ownership from pulse values. Same-session view changes release held controls; Stop, session changes and unknown command outcomes cancel repeat activity. Commands use monotonic `epoch:counter` operation IDs and no longer have a 128-write-per-Run limit. Unknown outcomes stop the session and are not retried.

For all configured variables, File → Export recent CSV exports the retained coherent capture with actual sequence, elapsed simulation time, source/variable identity, type, raw value, units, quality and reason. New captures also retain actual host receipt UTC; older captures leave it blank. Stop does not relabel captured frames as the new session.

In the desktop app, start Run and choose File → Start recording… to choose a **new** CSV file. Recording never overwrites an existing file. It consumes every accepted frame before graph decimation. File → Stop recording, Stop, project replacement and Close stop admission and flush the recording. Queued data is bounded to 2MiB with one in-flight chunk, at most 256 rows and 128KiB per JSON/CSV chunk. The development file limit is 256MiB. Queue overload, disk failure, file limit and uncertain five-second append/flush outcomes are visible; the simulator can continue, but the file is explicitly partial. Uncertain chunks are never retried. Continuous file recording requires the native app; bounded recent CSV export also works in the browser.

CSV uses the explicit `csv_text_encoding=spreadsheet-safe-v1` column. Text fields whose first character is an apostrophe, or whose first non-whitespace character is `=`, `+`, `-` or `@`, receive one leading apostrophe before standard CSV quoting. Decode marked text by removing exactly one leading apostrophe if present. Original leading apostrophes are therefore doubled, making this reversible. Numeric and boolean raw values are unaffected. The whitespace policy follows the JavaScript whitespace set and is mirrored explicitly by the Rust codec. Unicode, quotes and newlines are retained.

The graph uses stable transformed catalog Y limits by default, so constant/manual changes move vertically instead of moving the axis with the value. Explicit manual limits take priority. Time graphs default to connected lines; XY configurations without explicit `traceMode` now default to scatter points, and explicit connected trajectories remain supported. Current points and stopped/frozen status are visible. A manual X held constant correctly creates a vertical XY plot.


## Implementation and verification

`model.ts` and the shared workspace schema validate document state; Rust applies equivalent native load/save semantics. Static AJV generation keeps runtime CSP free of unsafe-eval. `provider.ts`/`engine.ts`/the simulator worker own the offline envelope/catalog/acquisition boundary. Main-window document state is authoritative; floating snapshots validate atomically before commit. `editor.ts`, `docking.ts`/`DockHost.tsx`, `Graph.tsx`/`plot.ts`, `recording.ts` and native recovery/recording modules implement the corresponding bounded slices. See ADRs [editor](19-offline-editor-decisions.md), [docking](20-docking-decisions.md), [lifecycle](21-offline-lifecycle-decisions.md), [recording](22-offline-recording-decisions.md) and [provider contract](17-provider-and-graph-contract.md).

Current source checks:102 frontend tests and13 Rust tests passed on Windows; production typecheck/build passed. This includes real App handler tests for recovery-clear failure/retry, held/repeat controls and uncertain outcomes, pending recording start/close and flush/replacement guards, atomic floating snapshots and symbol drag exclusion. Native recording tests cover two same-name sources with numeric/boolean quality metadata, safe creation, partial failure and validation before append. These automated results do not replace native GUI evidence; see [closure review](reviews/offline-closure.md).

For performance, open `examples/performance-200.olw.json` and enable View → Performance diagnostics. It contains200 widgets including four graphs and100 numeric variables at20Hz. Run visibly for two minutes and record median/p95 renderer/worker-receipt-to-commit/handler-to-rAF timings, heap where available,600-frame retention and recording queue limits. Use Measure response during Run; this measures handler-to-next-rAF, excluding queued input delay and completed paint. The opt-in `OLW_PERFORMANCE=1` model benchmark steps72,000 ticks (one simulated hour) and writes a bounded-state report; it is accelerated engine execution, not one hour of GUI/native runtime evidence.

Remaining verification: actual macOS/Linux interaction is owner-deferred; portable builds/CI remain required. Actual second-monitor/DPI restoration, final Windows native docking/multi-series/recording acceptance and visible GUI performance measurements are pending. There are no embedded providers, ELF/DWARF, target transports, real hardware writes, triggered target scope or durable Rust runtime-session ownership. The Windows executable is unsigned; signing/installers/notarization remain future release work. Browser Save starts a download and cannot confirm final filesystem completion; native recording/recovery use application-managed files. Docked secondary screen views are compact read/write views; activate the main screen or float it for full editing gestures. Floating Toolbox adds to its displayed destination through validated main authority. Floating Explorer activates screens or opens/focuses the main source configuration dialog; it does not host a competing document/source editor.
